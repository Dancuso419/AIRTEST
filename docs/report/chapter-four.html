CHAPTER FOUR

IMPLEMENTATION AND TESTING

4.0 Overview

This chapter presents the software implementation and verification details of the AIRTEST (Airtime Telemetry and Efficiency Stress Test) framework. It outlines the core features of the system, technical problems encountered during development, the strategies used to overcome these hurdles, comprehensive test plans across unit, integration, and system levels, the test traceability matrix, and a step-by-step user operational guide.

4.1 Main Features

The AIRTEST application delivers six primary feature modules, designed to allow network engineers and university administrators to intuitively evaluate wireless protocol performance under dense auditorium conditions.

4.1.1 Scenario Control & Parameter Matrix Selector

The Scenario Control panel enables operators to manipulate simulation variables dynamically. Users can toggle between client densities (10, 14, or 20 active stations), deployment topologies (1-AP centralized vs 3-AP multi-cell), and traffic profiles (Web Browsing, Video Streaming, Bulk Data Transfer). Selecting a parameter combination instantly queries the underlying telemetry store and updates all dashboard visualizations without page reloads.

4.1.2 Dual-Needle Cockpit Analog Gauges & Comparison Panel

Modeled after aircraft cockpit flight instruments, the primary telemetry panel features custom SVG analog dial gauges. Each gauge renders two distinct needles: a white needle representing legacy IEEE 802.11ac (Wi-Fi 5) performance and a vibrant green needle representing IEEE 802.11ax (Wi-Fi 6). Gauges display Throughput (Mbps), Airtime Utilization (%), Packet Loss (%), and Latency Jitter (ms) simultaneously, providing immediate visual contrast between protocol efficiencies.

4.1.3 Telemetry Distribution & Metric Switching System

The Metric Switching system allows operators to alter the primary diagnostic view between throughput-centric, latency-centric, and airtime-centric telemetry perspectives. The interface recalculates scale bounds dynamically, ensuring optimal visual precision regardless of whether metrics range from low-latency Web requests or high-bandwidth bulk file transfers.

4.1.4 Density Stress Curve Analysis Module

The Density Stress Curve module uses Recharts responsive vector graphics to plot protocol performance trajectories as client density increases from 10 to 20 active stations. The curves visually demonstrate the non-linear performance degradation of Wi-Fi 5 under CSMA/CA contention compared to the flat, stable response curve of Wi-Fi 6 powered by OFDMA sub-carrier scheduling.

4.1.5 Run Selection & Dataset Persistence Manager

The Dataset Persistence Manager handles client-side caching of pre-computed simulation telemetry. It allows users to switch between Seed 1 and Seed 2 simulation runs or compute aggregated averages across the 72-scenario matrix. The module guarantees instantaneous UI state restoration and zero network latency during offline demonstrations.

4.1.6 Airtime Efficiency & Protocol Diagnostic Engine

The Protocol Diagnostic Engine calculates derivative metrics from raw flow telemetry, specifically computing the **Airtime Efficiency Gain Ratio**. This engine isolates MAC layer preamble overhead from payload transmission time, displaying diagnostic summary cards that quantify exact airtime savings achieved by Wi-Fi 6 for the selected auditorium scenario.

4.2 Implementation Problems

During the design and construction of the AIRTEST pipeline, four significant technical challenges were encountered:

Table 4.1: Summary of Implementation Problems Encountered

Problem ID Subsystem Affected Technical Description of Problem
P-01 NS-3 C++ Simulation Engine Severe CPU execution slowdown (~9x execution time penalty) when running high-density (20 stations) Wi-Fi 6 OFDMA simulation matrix on developer workstation.
P-02 Python Telemetry Parser Division-by-zero exceptions in `parse.py` when processing short 3-second FlowMonitor XML files where zero packets were received by dropped flow IDs.
P-03 React UI Gauge Components SVG gauge needles suffered from visual jitter and erratic rotational jumps when switching rapidly between high and low parameter values.
P-04 Multi-AP Topology Simulation Overlapping BSS (OBSS) interference in 3-AP topology scenarios produced erratic packet loss spikes due to uncalibrated Clear Channel Assessment (CCA) thresholds.

4.3 Overcoming Implementation Problems

The technical problems identified in Section 4.2 were systematically resolved through engineering adjustments:

  • Resolution of P-01 (NS-3 CPU Slowdown): Implemented a non-threaded, sequential batch execution queue in `run_matrix.py` with explicit inter-scenario CPU cooling delays. Capped simulation measurement duration strictly to 3.0 seconds per scenario while preserving packet trace integrity.
  • Resolution of P-02 (Parser Division-by-Zero): Enforced rigorous defensive programming in `parse.py`. Added explicit checks checking if `rxPackets > 0` before calculating mean delay, jitter, or loss percentages, assigning default zero floats to inactive flows.
  • Resolution of P-03 (Gauge Needle Jitter): Utilized CSS cubic-bezier transition curves (`transition: transform 0.6s cubic-bezier(0.4, 0, 0.2, 1)`) combined with React `useMemo` hooks to memoize needle rotation angles, eliminating re-render flickering.
  • Resolution of P-04 (OBSS Interference Calibration): Explicitly configured NS-3 `SpectrumWifiPhy` CCA energy detection thresholds and enabled BSS Coloring headers (Color ID 1, 2, and 3 for the 3 APs), allowing spatial reuse mechanisms to correctly ignore distant BSS transmissions.

4.4 Testing

A multi-tiered testing strategy was executed to verify the mathematical accuracy, pipeline reliability, and user interface responsiveness of the AIRTEST framework.

4.4.1 Test Plans (Unit, Integration, and System Testing)

Testing was divided into three structured levels:

  • Unit Testing: Verifying individual Python parsing functions (`parse.py`) for correct mathematical calculation of throughput and latency sum, as well as verifying individual React UI components (`GaugeDial.jsx`, `StressChart.jsx`).
  • Integration Testing: Verifying end-to-end data flow from NS-3 FlowMonitor XML outputs into `results.json`, ensuring schema field types match expected dashboard interfaces.
  • System Testing: Executing full-scale user acceptance tests across multiple browser engines, verifying 60 FPS gauge rendering, offline persistence, and responsiveness across varying screen resolutions.

4.4.2 Test Suite Execution Summary

The automated test suite comprised **39 Python backend unit/integration tests** executed via `pytest` and **47 JavaScript frontend tests** executed via `vitest` and React Testing Library. All 86 test cases passed successfully (100% pass rate).

4.5 User Guide

To operate the AIRTEST visual telemetry dashboard, users follow these four simple operational steps:

  1. Launching the Application: Open a modern web browser and navigate to the AIRTEST local dashboard web URL (e.g., `http://localhost:5173`). The main Aircraft Cockpit Instrument Panel will load automatically.
  2. Configuring Scenario Filters: Use the top control toolbar to select the desired Client Density (10, 14, or 20 Stations), Topology (1-AP or 3-AP), and Traffic Profile (Web, Video Streaming, or Bulk Data).
  3. Interpreting Dual Cockpit Dials: Observe the central analog gauges. The White Needle indicates legacy Wi-Fi 5 performance, while the Green Needle indicates Wi-Fi 6 performance. Compare numerical readouts displayed beneath each dial.
  4. Analyzing Density Trends: Scroll down to the Density Stress Curves section to examine how throughput and airtime scale across 10, 14, and 20 clients. Review the Protocol Diagnostic Cards for automated ROI recommendations.
